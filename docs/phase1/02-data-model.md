# 02 — Data model

## In plain language

Every piece of data belongs either to **one company** ("tenant-scoped") or to **the whole system** ("global"). For every tenant-scoped table, the database itself checks on every read and write that the row belongs to the company the current request is working for. If our code forgets to filter, the database still says no.

Secrets are never stored in a readable form: the 3-digit code is stored only as a slow, peppered hash; session and enrollment tokens are stored only as SHA-256 hashes; authenticator-app seeds are stored encrypted.

## Conventions (apply to every table unless stated)

- Primary keys: `id uuid` generated by PostgreSQL 18's `uuidv7()` (time-ordered, not guessable in practice, but **not** treated as secret).
- Time: `timestamptz`, always UTC. `created_at` defaults to `now()`.
- Text enums are `text` + `CHECK (... IN (...))` — easy to extend in a migration, readable in SQL.
- **Tenant-scoped (T)** tables have `tenant_id uuid NOT NULL REFERENCES tenants(id)`, `ENABLE` + `FORCE ROW LEVEL SECURITY`, and one policy:
  `USING (tenant_id = app_current_tenant()) WITH CHECK (tenant_id = app_current_tenant())`
  where `app_current_tenant()` reads the per-transaction setting `app.tenant_id` and returns `NULL` (so: no rows) if it is unset or empty.
- Foreign keys between tenant-scoped tables are **composite** `(tenant_id, x_id)` so a row can never point at another tenant's row, even by mistake.
- **Global (G)** tables have no tenant column. The app role gets only the specific privileges listed.
- "Owner module" = the only module allowed to touch the table with SQL.

Legend for the **F#** column: the founder's feature number the table serves. *(design only)* = table/columns exist, no feature code in Phase 1.

### `cards` — T — F1, F3, F34

| state | text | `issued` \| `active` \| `suspended` \| `revoked` \| `expired` \| `replaced` |
| state_changed_at | timestamptz | |
| issued_at | timestamptz | |
| activated_at | timestamptz | NULLABLE |
| **expires_at** | timestamptz | NOT NULL — *renewal_state field* |

| created_at, updated_at | | |

Indexes: (tenant_id, state); (tenant_id, person_id); (tenant_id, expires_at); partial unique index: **at most one non-terminal card per person** (`WHERE state NOT IN ('revoked','replaced')`); partial unique index: **at most one non-terminal company card per tenant**.

A database trigger rejects any `state` change that is not in the legal-transition table (second line of defence; the first is the state machine in code).

### `card_directory` — G — F1
Maps a card number to its tenant so login can start before we know the tenant.
| Column | Type | Notes |
|---|---|---|
| card_number | char(16) | PK → global uniqueness |
| tenant_id, card_id | uuid | |

**The app role has no direct privileges on this table.** It can only call two `SECURITY DEFINER` functions: `resolve_card(card_number)` (exact match, returns one tenant_id + card_id or nothing) and `register_card(...)` (insert at issue time). So even a bug in our code cannot list all card numbers.

### `card_secrets` — T — F1, F34
One *current* row per card; older rows kept only as "retired" markers without usable hashes.
| Column | Type | Notes |
|---|---|---|
| id, tenant_id, card_id | uuid | |
| sc_hash | text | Argon2id PHC string of `HMAC-SHA-256(pepper, SC)`. **Never the SC.** Set to NULL when retired. |
| pepper_id | text | which pepper version was used, e.g. `v1` |
| status | text | `current` \| `retired` |
| created_at, retired_at | timestamptz | |
| created_by_card_id | uuid | |

Partial unique index: one `current` row per card. The app role may SELECT `sc_hash` only for the card being authenticated (column never appears in any API response; a test greps responses).

### `card_auth_state` — T — lockout state (F3, security req. 4)

| Column | Type | Notes |
|---|---|---|
| tenant_id, card_id | uuid | PK |
| sc_failed_count | int | consecutive wrong SCs **after** a valid strong factor |
| locked_at | timestamptz | NULLABLE — non-null means SC-locked |
| lock_reason | text | `sc_attempts` \| `admin` \| `anomaly` *(anomaly: F5 design only)* |
| factor_failed_count | int | failed strong-factor attempts in the current window |
| factor_throttled_until | timestamptz | NULLABLE — temporary, auto-expiring |
| last_totp_step | bigint | NULLABLE — last accepted TOTP time step (replay protection) |
| last_login_at | timestamptz | |

### `login_attempts` — G — security req. 5
Internal record of **every** login attempt including unknown cards (which have no tenant).
| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| occurred_at | timestamptz | |
| card_number_hmac | bytea | HMAC of the submitted number with a server key — never the raw number for unknown cards |
| tenant_id, card_id | uuid | NULLABLE (NULL = unknown card) |
| ip_hash | bytea | HMAC of the IP |
| outcome | text | `success` \| `fail` |
| real_reason | text | `unknown_card` \| `bad_factor` \| `bad_sc` \| `locked` \| `expired` \| `state` \| `throttled` \| … **internal only, never returned** |

App role: INSERT only. Read by operators through the migration/backup role. Rows older than 90 days are deleted by a maintenance job.

### `credentials` — T — strong factors (passkeys / TOTP)
| Column | Type | Notes |
|---|---|---|

| webauthn_credential_id | bytea | UNIQUE (global), passkey only |
| webauthn_public_key | bytea | passkey only (public — not a secret) |
| webauthn_sign_count | bigint | clone detection |
| webauthn_transports | text[] | |

### `enrollment_tokens` — T
One-time, high-entropy tokens that let a new cardholder attach their first strong factor.
`id`, `tenant_id`, `card_id`, `token_hash bytea` (SHA-256; UNIQUE), `purpose` (`initial` \| `reset`), `expires_at` (default 72 h), `used_at`, `created_by_card_id`, `created_at`.

### `login_transactions` — T
Short-lived state for one login in progress (holds the WebAuthn challenge).
`id`, `tenant_id` (the platform tenant for unknown cards), `card_id` NULLABLE, `txn_hash bytea` UNIQUE, `webauthn_challenge bytea`, `expires_at` (5 minutes), `consumed_at`, `ip_hash`, `created_at`.

### `sessions` — T — security req. 6
| Column | Type | Notes |
|---|---|---|
| id, tenant_id, card_id | uuid | |
| token_hash | bytea | SHA-256 of the opaque session token. UNIQUE. **The token itself is never stored.** |
| csrf_hash | bytea | SHA-256 of the CSRF token bound to this session |
| credential_id | uuid | which strong factor was used |
| created_at | timestamptz | |
| last_seen_at | timestamptz | idle timeout |
| idle_expires_at, absolute_expires_at | timestamptz | |
| revoked_at | timestamptz | NULLABLE |
| revoked_reason | text | `logout` \| `card_suspended` \| `card_revoked` \| `card_expired` \| `card_replaced` \| `privilege_change` \| `sc_rotated` \| `admin` |

| ip_hash, user_agent_hash | bytea | |

### `card_events` — T — F5 usage history
Append-only (INSERT + SELECT for the app role).
`id`, `tenant_id`, `card_id`, `occurred_at`, `event_type` (`issued`, `activated`, `login_success`, `login_failed`, `sc_locked`, `unlocked`, `suspended`, `reinstated`, `revoked`, `expired`, `renewed`, `replaced`, `role_assigned`, `role_removed`, `limit_exceeded`, `credential_added`, `credential_removed`), `actor_card_id` NULLABLE, `request_id`, `metadata jsonb` (no secrets, no PII).
Index: (tenant_id, card_id, occurred_at DESC).

### `card_limits` and `card_usage_counters` — T — F5
`card_limits`: `tenant_id`, `card_id`, `limit_key` (e.g. `requests_per_day`, `exports_per_day`), `window_seconds`, `max_count`. PK (tenant_id, card_id, limit_key).
`card_usage_counters`: `tenant_id`, `card_id`, `limit_key`, `window_start`, `count`. PK on all four key columns. Incremented atomically (`INSERT … ON CONFLICT DO UPDATE`).
**Anomaly lock (F5) is design only:** the hook is `card_auth_state.lock_reason = 'anomaly'` plus a future `card_anomaly_signals` table; no detection code in Phase 1.

## C. Roles and permissions (owner: identity-access)

### `roles` — G — F2
`role_key` PK: `company_owner`, `admin`, `department_manager`, `expert`, `successor`, `reviewer`, `auditor`, `contractor`. Plus `display_name`, `rank int` (owner 100 … contractor 10; used by the "cannot grant a role above your own" rule), `pilot_enabled boolean`.
All 8 are seeded. Which ones a tenant may use is `tenant_settings.enabled_roles`.

### `permissions` — G — F2
`permission_key` PK, formatted `resource:action` (e.g. `card:suspend`), `description`, `is_write boolean` (drives the read-only grace rule), `platform_only boolean`.

### `role_permissions` — G — F2 (the matrix)
| Column | Notes |
|---|---|
| role_key, permission_key | PK |
| scope | `tenant` \| `department` \| `own` — how wide the grant is |
| max_sensitivity | smallint, default 0 — highest data-sensitivity label this grant reaches (0 public-internal … 3 restricted). Used from Phase 2. |
| grant_source | `base` \| `pilot_reviewer` — rows marked `pilot_reviewer` apply only while `tenant_settings.pilot_reviewer_grant` is true |

App role: SELECT only on all three. Tenants cannot edit the matrix in Phase 1.

### `card_roles` — T — F2
`tenant_id`, `card_id`, `role_key`, `department_id` NULLABLE (scope for department-level roles), `assigned_by_card_id`, `assigned_at`. PK (tenant_id, card_id, role_key).

## D. Audit, idempotency, operations (owner: platform)

### `audit_log` — T — F20
Append-only. App role: **INSERT and SELECT only**; a trigger additionally blocks UPDATE, DELETE and TRUNCATE for every role.
| Column | Type | Notes |
|---|---|---|
| tenant_id | uuid | system events with no tenant use the platform tenant |
| seq | bigint | per-tenant, gap-free, assigned by trigger. PK (tenant_id, seq) |
| occurred_at | timestamptz | assigned by trigger |
| actor_card_id | uuid | NULLABLE (anonymous / system) |
| actor_kind | text | `card` \| `system` \| `anonymous` \| `service` |
| action | text | e.g. `card:suspend` |
| resource_type, resource_id | text | |
| decision | text | `allow` \| `deny` \| `event` |
| reason_code | text | e.g. `ALLOW_ROLE`, `DENY_DEFAULT`, `DENY_TENANT_MISMATCH` |
| request_id | text | |
| ip | inet | |
| details | text | canonical JSON string; whitelisted keys only; never secrets or full PII |
| prev_hash | bytea | hash of the previous row in this tenant's chain (32 zero bytes for seq 1) |
| row_hash | bytea | SHA-256 over prev_hash + every column above, in a fixed, documented encoding |

Indexes: (tenant_id, occurred_at); (tenant_id, actor_card_id, occurred_at); (tenant_id, resource_type, resource_id).

### `audit_chain_heads` — T
`tenant_id` PK, `last_seq`, `last_hash`. Written only by the audit trigger (the app role has SELECT only). Locking this row serialises inserts per tenant so the chain never forks.

### `audit_anchors` — T
Record of each time the chain head was copied to the external write-once-style bucket: `tenant_id`, `seq`, `row_hash`, `anchored_at`, `object_uri`.

### `idempotency_keys` — T — security req. 12
`tenant_id`, `actor_card_id`, `key` (client-supplied, ≤ 128 chars), `operation_id`, `request_hash bytea`, `status` (`in_progress` \| `done`), `response_status int`, `response_body jsonb` (**with one-time secrets stripped** — see `03`), `resource_id`, `created_at`, `expires_at` (24 h). PK (tenant_id, actor_card_id, key).

### `rate_limit_buckets` — G — security req. 5
`bucket_key bytea` (HMAC of e.g. `ip:…`, `card:…`, `global:login`), `window_start timestamptz`, `count int`. PK (bucket_key, window_start). Atomic upsert. Old windows deleted by the maintenance job.

### `export_jobs` — T — F30
`id`, `tenant_id`, `requested_by_card_id`, `status` (`queued` \| `running` \| `done` \| `failed`), `format` (`jsonl+csv`), `manifest jsonb` (table names, row counts, SHA-256 per file), `created_at`, `completed_at`.

### `schema_migrations` — G
Managed by dbmate.

## Scope summary

**Global (8):** `roles`, `permissions`, `role_permissions`, `plan_limits`, `card_directory`, `login_attempts`, `rate_limit_buckets`, `schema_migrations`.

**Tenant-scoped with row-level security (25):** `tenants`, `tenant_settings`, `departments`, `people`, `cards`, `card_secrets`, `card_auth_state`, `credentials`, `enrollment_tokens`, `login_transactions`, `sessions`, `card_events`, `card_limits`, `card_usage_counters`, `card_roles`, `audit_log`, `audit_chain_heads`, `audit_anchors`, `idempotency_keys`, `export_jobs`, `outbox_events`, `webhook_endpoints`, `analytics_events`, `card_tokens`, `sso_connections`.
*(`tenants` is scoped by its own `id`; the other 24 by `tenant_id`.)*

A test (Step 5) queries the PostgreSQL catalogue and **fails if any table has a `tenant_id` column but lacks forced row-level security**, so a future table cannot be added without it.

## Database roles

| Role | Can log in | Purpose | Key properties |
|---|---|---|---|
| `legacyai_owner` | no | Owns all objects | — |
| `legacyai_migrator` | yes | Runs migrations (member of owner) | Never used by the running API |
| `legacyai_app` | yes | The running API | `NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE`; per-table grants only. **At start-up the API checks its own role and refuses to run if it is a superuser or can bypass RLS.** |
| `legacyai_backup` | yes | Nightly `pg_dump` | Read-only, `BYPASSRLS` (a backup must see all tenants) |

On Neon, the console-created role inherits `BYPASSRLS` (verified, see `DEPENDENCIES.md`), so it serves as migrator/backup; `legacyai_app` is created by SQL so it gets none of that.
